# ওয়েবসাইট চালু করার নির্দেশিকা — মাহারাত মডেল মাদ্রাসা

এই নির্দেশিকা তাঁদের জন্য যাঁরা প্রোগ্রামার নন। ধাপগুলো পরপর অনুসরণ করলে GitHub-এ রাখা কোড থেকে
Hostinger-এ সাইট চালু হয়ে যাবে। শেষে Vercel ও Google Cloud Run-এর সংক্ষিপ্ত নিয়মও আছে।

> **মনে রাখুন:** Hostinger মাঝে মাঝে মেনু ও বোতামের নাম সামান্য বদলায়। নিচের নাম হুবহু না মিললে
> কাছাকাছি নামের বোতামটি বেছে নিন।

> **নিরাপত্তা:** পাসওয়ার্ড, `DATABASE_URL`, `JWT_SECRET` বা API কী কখনো GitHub-এ, চ্যাটে বা কোডে
> লিখবেন না। এগুলো শুধু হোস্টিংয়ের **Environment variables** অংশে বসাবেন।

## সাইট দুইভাবে চলতে পারে

| অবস্থা | কখন | কী হয় |
|---|---|---|
| **ডাটাবেস মোড** (আসল সাইট) | `DATABASE_URL` দেওয়া থাকলে | সব তথ্য MySQL ডাটাবেসে স্থায়ীভাবে জমা থাকে |
| **ডেমো মোড** | `DATABASE_URL` না থাকলে | সাইট নমুনা তথ্য নিয়ে চলে; কিছুই স্থায়ীভাবে সেভ হয় না, আর অ্যাডমিন লগইন বন্ধ থাকে |

## ১. Hostinger-এ সাইট চালু করা

যা লাগবে: Hostinger-এর এমন একটি প্ল্যান যাতে **Node.js অ্যাপ** চালানো যায় (Business বা Cloud), এবং
GitHub অ্যাকাউন্ট যেখানে `alaminbd7598/mmm` রিপোজিটরি আছে।

### ধাপ ১ — GitHub থেকে ওয়েবসাইট যোগ করুন

1. hPanel-এ ঢুকে **Websites → Add Website** চাপুন।
2. **Node.js app** বেছে নিন।
3. **Connect Git provider → Continue with GitHub** চাপুন এবং GitHub-এ লগইন করে অনুমতি দিন।
4. রিপোজিটরি হিসেবে **`alaminbd7598/mmm`** এবং ব্রাঞ্চ হিসেবে **`main`** বেছে নিন।
5. Hostinger সাধারণত নিজে থেকেই বুঝে নেয় এটি Next.js অ্যাপ। সেটিংস দেখতে চাইলে এগুলো থাকা উচিত:

   | ঘর | মান |
   |---|---|
   | Framework | Next.js |
   | Node.js version | 22 (অথবা 24) |
   | Install command | `npm install` |
   | Build command | `npm run build` |
   | Start command | `npm start` |

6. ডোমেইন বেছে নিয়ে ওয়েবসাইট তৈরি শেষ করুন।

এই মুহূর্তে সাইটটি **ডেমো মোডে** চালু হবে। পরের ধাপগুলোতে ডাটাবেস যুক্ত করলে আসল সাইট হয়ে যাবে।

### ধাপ ২ — ডাটাবেস তৈরি করুন

1. সদ্য তৈরি হওয়া ওয়েবসাইটের ভেতরে **Databases** অংশে যান।
2. **Hostinger MySQL** কার্ডে **+ Create** চাপুন।
   - **"Assign from plan"** দিয়ে পুরনো কোনো ডাটাবেস যুক্ত করবেন না; নতুন, খালি ডাটাবেস দরকার।
   - Supabase বা MongoDB কার্ড এই সাইটের জন্য নয়; ওগুলো এড়িয়ে যান।
3. ডাটাবেসের নাম, ইউজারনেম ও একটি শক্ত পাসওয়ার্ড দিন। পাসওয়ার্ডে শুধু ইংরেজি অক্ষর ও সংখ্যা রাখুন
   (`@ : / # ? $ %` জাতীয় চিহ্ন বাদ দিন), তাহলে পরের ধাপে কোনো ঝামেলা হবে না।
4. তৈরি হওয়ার পর Hostinger যে পূর্ণ নাম দেখায় তা টুকে রাখুন, যেমন:
   - ডাটাবেস: `u123456789_mmm`
   - ইউজার: `u123456789_mmmuser`
   - হোস্ট: সাধারণত `localhost` (Hostinger অন্য কিছু দেখালে সেটিই ব্যবহার করুন)

এগুলো দিয়ে `DATABASE_URL` এভাবে সাজান (এক লাইনে, ফাঁকা জায়গা ছাড়া):

```
mysql://u123456789_mmmuser:আপনার_পাসওয়ার্ড@localhost:3306/u123456789_mmm
```

### ধাপ ৩ — Environment variables বসান

ওয়েবসাইটের **Environment variables** অংশে নিচের নামগুলো হুবহু (বড় হাতের অক্ষরে) যোগ করুন:

| নাম | কী বসাবেন |
|---|---|
| `DATABASE_URL` | ধাপ ২-এ সাজানো ঠিকানা |
| `JWT_SECRET` | কমপক্ষে ৩২ অক্ষরের এলোমেলো লেখা (ইংরেজি অক্ষর ও সংখ্যা)। কাউকে জানাবেন না; একবার বসানোর পর আর বদলাবেন না |
| `ADMIN_BOOTSTRAP_PASSWORD` | প্রথম লগইনের সাময়িক পাসওয়ার্ড: কমপক্ষে ১২ অক্ষর, অক্ষর ও সংখ্যা মিলিয়ে। `admin123`-এর মতো সহজ পাসওয়ার্ড গ্রহণ করা হয় না |
| `NEXT_PUBLIC_APP_URL` | সাইটের পূর্ণ ঠিকানা, যেমন `https://www.আপনার-ডোমেইন.com` |
| `GEMINI_API_KEY` (ঐচ্ছিক) | Noor AI চ্যাটবট ও AI ফিচার চালাতে চাইলে Google Gemini API কী। না দিলে চ্যাটবট নির্ধারিত উত্তর দিয়ে চলে |

### ধাপ ৪ — Redeploy করুন

**Deployments → Redeploy** চাপুন। এই সময় সাইট নতুন করে তৈরি (build) হয় এবং ডাটাবেসের টেবিলগুলো
**নিজে থেকেই** তৈরি হয়ে যায়; আলাদা কিছু করতে হবে না। বিল্ড লগে এই লাইনগুলো দেখলে বুঝবেন সব ঠিক আছে:

```
[prepare-db] Syncing database tables with prisma db push ...
Your database is now in sync with your Prisma schema.
```

> Environment variables-এ কিছু বদলালে প্রতিবার **Redeploy** করতে হয়, নইলে পরিবর্তন কার্যকর হয় না।

### ধাপ ৫ — প্রথম লগইন

1. ব্রাউজারে `https://আপনার-ডোমেইন/admin` খুলুন।
2. ইউজার আইডি **`admin`** এবং পাসওয়ার্ড হিসেবে `ADMIN_BOOTSTRAP_PASSWORD`-এ যা বসিয়েছিলেন তা দিন।
3. লগইনের সঙ্গে সঙ্গে নিজের **নতুন পাসওয়ার্ড** ঠিক করতে বলা হবে (কমপক্ষে ১০ অক্ষর, অক্ষর ও সংখ্যা দুটোই)।
   নতুন পাসওয়ার্ড না দেওয়া পর্যন্ত ড্যাশবোর্ড খুলবে না।
4. এরপর Environment variables থেকে `ADMIN_BOOTSTRAP_PASSWORD` মুছে দিতে পারেন; এটি আর কাজে লাগে না।
5. অন্য স্টাফদের অ্যাকাউন্ট **User Roles & RBAC Matrix** ট্যাব থেকে তৈরি করুন। আপনি যে পাসওয়ার্ড দেবেন,
   সংশ্লিষ্ট স্টাফকে প্রথম লগইনে সেটি বদলে নিতে হবে।

জেনে রাখুন: নতুন ডাটাবেসে `admin` ছাড়াও সার্টিফিকেটে যাঁদের স্বাক্ষর ছাপা হয় সেই তিনজনের (চেয়ারম্যান,
অধ্যক্ষ, কো-অর্ডিনেটর) প্রোফাইল তৈরি থাকে। আপনি পাসওয়ার্ড ঠিক করে না দেওয়া পর্যন্ত তাঁরা লগইন করতে পারেন না।

### ধাপ ৬ — সাইট ঠিক আছে কি না দেখুন

ব্রাউজারে `https://আপনার-ডোমেইন/api/health` খুলুন। এমন লেখা দেখালে সব ঠিক আছে:

```
{"ok":true,"mode":"database","db":"up"}
```

- `"mode":"demo"` দেখালে `DATABASE_URL` বসানো হয়নি, অথবা বসানোর পর Redeploy করা হয়নি।
- `"db":"down"` দেখালে সাইট ডাটাবেসে পৌঁছাতে পারছে না; নিচের "সমস্যা হলে" অংশ দেখুন।

সাইট চালু আছে কি না নজরে রাখার সেবায় (uptime monitor) এই ঠিকানাটিই দিন।

### পরে কোড আপডেট হলে

GitHub-এর `main` ব্রাঞ্চে নতুন কোড এলে **Deployments → Redeploy** চাপুন (স্বয়ংক্রিয় ডিপ্লয় চালু থাকলে
নিজে থেকেই হবে)। ডাটাবেসের তথ্য যেমন আছে তেমনই থাকে।

## ২. পুরনো সাইটের তথ্য নতুন সাইটে আনা

**ক. অ্যাডমিন প্যানেলের ব্যাকআপ ফাইল থাকলে** (যে `.json` ফাইল "সম্পূর্ণ ব্যাকআপ ডাউনলোড" বোতাম দিয়ে নামানো হয়েছিল):

1. `admin` হিসেবে লগইন করুন।
2. **Backup, Restore & AI Extractor** ট্যাবে যান।
3. **ব্যাকআপ ফাইল আপলোড করুন** বোতামে ফাইলটি দিন।

**খ. পুরনো সার্ভারের `live-cms-state.json` ফাইল থাকলে** (অথবা ফাইলটি ১০ MB-এর বেশি বড় হলে): এই কাজটি
একজন ডেভেলপারকে দিয়ে করান। তিনি কোডের ফোল্ডারে `DATABASE_URL` বসিয়ে একবার এই কমান্ড চালাবেন:

```bash
npm run db:import -- path/to/backup.json
```

পুরনো ফাইলে থাকা পাসওয়ার্ডগুলো নিরাপদ রূপে (bcrypt) সংরক্ষিত হয় এবং প্রত্যেককে পরের লগইনে নতুন পাসওয়ার্ড
দিতে হয়। পুরনো সহজ পাসওয়ার্ড (`admin123` ইত্যাদি) আনা হয় না।

## ৩. সমস্যা হলে

প্রথমে ওয়েবসাইটের **Deployments** অংশে শেষ ডিপ্লয়ের **Build logs** এবং **Runtime logs** খুলে দেখুন। সাধারণ
সমস্যা ও সমাধান:

| যা দেখছেন | কারণ ও করণীয় |
|---|---|
| বিল্ড লগে `prisma db push failed` বা `Access denied` | `DATABASE_URL`-এর ইউজার, পাসওয়ার্ড বা ডাটাবেসের নাম মিলছে না। ধাপ ২-এর তথ্যের সঙ্গে মিলিয়ে ঠিক করে Redeploy করুন |
| বিল্ড লগে লাল রঙে `error TS...` | কোডে ভুল আছে। ডেভেলপারকে জানান; আগের ডিপ্লয়টি চালু থাকবে |
| বিল্ড মাঝপথে `Killed` লিখে থেমে যায় | বিল্ডের জন্য মেমোরি কম পড়েছে (প্রায় ১.৩ GB লাগে)। আবার Redeploy করুন; বারবার হলে Hostinger সাপোর্টকে জানান বা বড় প্ল্যান নিন |
| লগইন পাতায় "সেটআপ সম্পূর্ণ হয়নি" জাতীয় নির্দেশনা | `JWT_SECRET` (কমপক্ষে ৩২ অক্ষর) বা `ADMIN_BOOTSTRAP_PASSWORD` (কমপক্ষে ১২ অক্ষর) বসানো হয়নি বা নিয়ম মানেনি। ঠিক করে Redeploy করুন |
| Runtime logs-এ `ADMIN_BOOTSTRAP_PASSWORD ... refused` | পাসওয়ার্ডটি খুব ছোট বা খুব সহজ। আরও শক্ত পাসওয়ার্ড দিন |
| `/api/health`-এ `"db":"down"`, সাইটে "সাময়িক সমস্যা" বার্তা | ডাটাবেস সাড়া দিচ্ছে না। hPanel-এ ডাটাবেস চালু আছে কি না দেখুন; `DATABASE_URL`-এর হোস্ট ঠিক আছে কি না মিলিয়ে নিন |
| Runtime logs-এ `[rate-limit] No client address from the proxy` | ক্ষতিকর কিছু নয়; ডেভেলপারকে জানান (নিচের "ডেভেলপারদের জন্য" অংশে `TRUSTED_PROXY_HOPS` দেখুন) |
| ভিজিটরের ছবি/সিভি আপলোড হচ্ছে না, লগে আপলোড-সীমার কথা | জমা থাকা ফাইলের সীমা পূর্ণ হয়েছে। পুরনো লিড বা আবেদন মুছুন, অথবা `MAX_STORED_UPLOAD_MB` বাড়ান |

সমাধান না হলে লগের লেখাটুকু কপি করে ডেভেলপারকে পাঠান। **পাসওয়ার্ড বা `DATABASE_URL` কখনো পাঠাবেন না।**

## ৪. Vercel (প্রিভিউ বা ডেমোর জন্য)

1. vercel.com → **Add New → Project** → GitHub থেকে `alaminbd7598/mmm` বেছে নিন। Framework নিজে থেকেই
   **Next.js** ধরা পড়বে; কোনো সেটিংস বদলাতে হবে না।
2. **Deploy** চাপুন। `DATABASE_URL` না দিলে সাইট ডেমো মোডে চলবে।
3. ডেমোতে অ্যাডমিন প্যানেল দেখাতে চাইলে `DEMO_MODE=1` এবং একটি `JWT_SECRET` দিন। নমুনা অ্যাকাউন্টের
   পাসওয়ার্ড সবার জানা, তাই **আসল সাইটে কখনো `DEMO_MODE` দেবেন না।**
4. Vercel-এ আসল তথ্য রাখতে চাইলে বাইরের MySQL ডাটাবেসের `DATABASE_URL` দিন (Hostinger-এর ডাটাবেস হলে
   hPanel-এ **Remote MySQL** চালু করতে হবে)। মনে রাখুন, `DATABASE_URL` থাকলে প্রতিটি বিল্ড, এমনকি প্রিভিউ
   বিল্ডও, ওই ডাটাবেসের টেবিল হালনাগাদ করে।

Vercel-এ অতিরিক্ত অনুরোধ ঠেকানোর সীমাগুলো আংশিকভাবে কাজ করে, আর একবারে ৪ MB-এর বেশি তথ্য পাঠানো যায় না।
তাই চূড়ান্ত লাইভ সাইটের জন্য Hostinger বা Cloud Run ব্যবহার করুন।

## ৫. Google Cloud Run (Docker)

রিপোজিটরিতে `Dockerfile` আছে। Google Cloud SDK ইনস্টল থাকলে:

```bash
gcloud run deploy mmm-web --source . --region asia-south1 --allow-unauthenticated --port 8080
```

এরপর Cloud Run কনসোলে **Edit & deploy new revision → Variables & Secrets**-এ ধাপ ৩-এর ভেরিয়েবলগুলো দিন।
ডাটাবেস হিসেবে Cloud SQL (MySQL) বা বাইরের MySQL ব্যবহার করুন।

Docker ইমেজ তৈরির সময় ডাটাবেসে হাত দেওয়া হয় না। তাই প্রথমবার, এবং পরে ডাটাবেসের গঠন বদলালে, কোডের ফোল্ডার
থেকে একবার চালান:

```bash
DATABASE_URL="mysql://..." npm run db:push
```

## ডেভেলপারদের জন্য: সব Environment variable

| নাম | বাধ্যতামূলক? | কাজ |
|---|---|---|
| `DATABASE_URL` | আসল সাইটে হ্যাঁ | `mysql://ইউজার:পাসওয়ার্ড@হোস্ট:3306/ডাটাবেস`। পাসওয়ার্ডে বিশেষ চিহ্ন থাকলে URL-encode করুন (`@` → `%40`) |
| `JWT_SECRET` | `DATABASE_URL` থাকলে হ্যাঁ | লগইন সেশন স্বাক্ষরের গোপন কী, কমপক্ষে ৩২ অক্ষর |
| `ADMIN_BOOTSTRAP_PASSWORD` | প্রথম লগইনে হ্যাঁ | `admin`-এর প্রাথমিক পাসওয়ার্ড (১২+ অক্ষর, অক্ষর ও সংখ্যা) |
| `NEXT_PUBLIC_APP_URL` | সুপারিশকৃত | সাইটের ঠিকানা; canonical লিংক, sitemap ও সার্টিফিকেটের QR-এ ব্যবহৃত হয়। না দিলে যে ঠিকানায় অনুরোধ আসে সেটিই ধরা হয় |
| `GEMINI_API_KEY` | না | Google Gemini API কী |
| `GEMINI_MODEL` | না | ডিফল্ট `gemini-4-hydrogen` |
| `BLOG_API_KEY` | না | ব্লগ অটোমেশন ওয়েবহুকের নির্দিষ্ট কী |
| `TRUSTED_PROXY_HOPS` | না | অ্যাপের সামনে কয়টি প্রক্সি আছে (ডিফল্ট `1`)। সামনে Cloudflare বা Load Balancer বসালে `2` |
| `MAX_STORED_UPLOAD_MB` | না | ভিজিটরদের আপলোড করা ছবি ও সিভির মোট সীমা (ডিফল্ট `160`) |
| `CHAT_DAILY_LIMIT` | না | চ্যাটবটে দিনে মোট কতটি AI উত্তর দেওয়া হবে (ডিফল্ট `3000`) |
| `DEMO_MODE` | না | ডাটাবেস ছাড়া লাইভ সার্ভারে ডেমো অ্যাডমিন চালু করতে `1` (শুধু ডেমোর জন্য) |
| `SKIP_DB_PUSH` | না | `1` দিলে বিল্ডের সময় টেবিল তৈরি/হালনাগাদ বাদ যায় (বিল্ড-সার্ভার ডাটাবেসে পৌঁছাতে না পারলে); তখন নিজে `npm run db:push` চালাতে হবে |

`.env.example` ফাইলে প্রতিটি নাম ব্যাখ্যাসহ আছে। নিজের কম্পিউটারে চালানো, পরীক্ষা (test) ও দৈনন্দিন
রক্ষণাবেক্ষণের নিয়ম [MAINTENANCE.bn.md](MAINTENANCE.bn.md)-এ দেখুন।

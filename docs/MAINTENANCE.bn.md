# রক্ষণাবেক্ষণ নির্দেশিকা — মাহারাত মডেল মাদ্রাসা ওয়েবসাইট

এই নির্দেশিকার প্রথম তিনটি অংশ মাদ্রাসার দায়িত্বশীলদের জন্য (প্রোগ্রামিং জানার দরকার নেই)। শেষ তিনটি অংশ
ডেভেলপারদের জন্য। সাইট প্রথমবার চালু করার নিয়ম [DEPLOYMENT.bn.md](DEPLOYMENT.bn.md)-এ আছে।

## ১. প্রতিদিনের কাজ: অ্যাডমিন প্যানেল

সাইটের প্রায় সব লেখা, ছবি ও তথ্য **কোড না ছুঁয়েই** অ্যাডমিন প্যানেল থেকে বদলানো যায়।
`https://আপনার-ডোমেইন/admin` ঠিকানায় লগইন করুন। কোন কাজ কোন ট্যাবে:

| কাজ | ট্যাব |
|---|---|
| ভর্তির আবেদন ও অভিভাবকদের জিজ্ঞাসা দেখা, অবস্থা বদলানো | লিড টু অ্যাডমিশন (Lead to Admission) |
| ভর্তি টোকেন ও ছাড় | Admission Token 2027 |
| নোটিশ প্রকাশ | Notice Board Manager |
| উপরের চলমান খবর | Scrolling News Ticker |
| অনুষ্ঠান ও সেমিনার | Events & Seminars |
| ছুটি ও বাৎসরিক ক্যালেন্ডার | Institutional Academic Calendar |
| পাঠ্যক্রম ও সিলেবাস | Curriculum & Syllabus |
| ফি, পপ-আপ ও Noor AI চ্যাটবট | Popup, MMM AI Agent & Fee Calculator |
| শিক্ষা পদ্ধতি, ১০ বছরের পরিকল্পনা, ডে-কেয়ার রুটিন, পরিবহন, অভিযোগ | Madrasah Infographics & Transport |
| ভিডিও, ফটো গ্যালারি, হিফজ ট্রি | মিডিয়া শোকেস (Media Showcase & Hifz Tree) |
| ব্লগ | Blog & Articles Manager |
| নিয়োগ বিজ্ঞপ্তি ও চাকরির আবেদন | ক্যারিয়ার ও নিয়োগ ব্যবস্থাপনা (Career & Hiring) |
| শিক্ষকদের ছুটি | Teacher Leave Management |
| ভার্চুয়াল অফিস | Virtual Office Live Desk |
| লোগো, রং ও মোবাইলের নিচের বার | Branding, Logo Vault & Mobile Bar |
| ঠিকানা, ফোন, ম্যাপ ও সাধারণ সেটিংস | Campus Maps & Site Settings |
| স্টাফ অ্যাকাউন্ট ও কে কী করতে পারবেন | User Roles & RBAC Matrix |
| ব্যাকআপ ও রিস্টোর | Backup, Restore & AI Extractor |

কয়েকটি জরুরি কথা:

- পরিবর্তন করার পর উপরে **"সংরক্ষণ বাকি আছে"** চিহ্ন দেখালে ইন্টারনেট সংযোগ দেখুন এবং চিহ্নটি চলে না যাওয়া
  পর্যন্ত ট্যাব বন্ধ করবেন না।
- একই জিনিস দুজন একসঙ্গে সম্পাদনা করলে পরে যিনি সেভ করেন তাঁকে একটি বার্তা দেখানো হয় এবং নতুন তথ্য লোড হয়।
  তখন নিজের পরিবর্তনটি আবার করুন।
- প্রত্যেক স্টাফের আলাদা অ্যাকাউন্ট রাখুন; একই পাসওয়ার্ড কয়েকজন মিলে ব্যবহার করবেন না। কেউ দায়িত্ব ছাড়লে
  **User Roles & RBAC Matrix** ট্যাব থেকে তাঁর অ্যাকাউন্ট মুছে দিন।
- পাসওয়ার্ড ভুলে গেলে সুপার অ্যাডমিন ওই ট্যাব থেকেই নতুন পাসওয়ার্ড ঠিক করে দিতে পারেন। সুপার অ্যাডমিন
  নিজে ভুলে গেলে ডেভেলপারের সাহায্য নিন।

## ২. ব্যাকআপ ও রিস্টোর

**ব্যাকআপ নেওয়া (মাসে অন্তত একবার, এবং বড় কোনো পরিবর্তনের আগে):**

1. সুপার অ্যাডমিন হিসেবে লগইন করে **Backup, Restore & AI Extractor** ট্যাবে যান।
2. **সম্পূর্ণ ব্যাকআপ ডাউনলোড (.json)** চাপুন। `maharat_madrasah_cms_backup_তারিখ.json` নামে একটি ফাইল নামবে।
3. ফাইলটি নিরাপদ জায়গায় রাখুন (যেমন মাদ্রাসার Google Drive-এর এমন ফোল্ডার যা শুধু দায়িত্বশীলরা দেখতে পারেন)।
   এতে অভিভাবকদের নাম ও ফোন নম্বর থাকে, তাই কাউকে পাঠাবেন না।

**রিস্টোর করা:** একই ট্যাবে **ব্যাকআপ ফাইল আপলোড করুন** বোতামে ফাইলটি দিন। সাইটের বর্তমান তথ্য ওই ফাইলের
তথ্য দিয়ে বদলে যাবে, তাই রিস্টোরের আগে বর্তমান অবস্থার একটি ব্যাকআপ নামিয়ে রাখুন। সুপার অ্যাডমিন ছাড়া অন্য
কেউ রিস্টোর করলে শুধু সেই অংশগুলো বদলায় যেগুলোর পূর্ণ অনুমতি তাঁর আছে; স্টাফ অ্যাকাউন্ট ও অনুমতির তালিকা
সুপার অ্যাডমিন ছাড়া কেউ বদলাতে পারেন না।

**ডাটাবেসের পূর্ণ কপি:** Hostinger-এর hPanel-এ ডাটাবেসের জন্য আলাদা ব্যাকআপ সুবিধা আছে (Databases বা
Backups অংশে)। সেটিও চালু রাখুন; এটি স্টাফদের পাসওয়ার্ডসহ সবকিছুর কপি রাখে, যা JSON ব্যাকআপে থাকে না।

## ৩. কখন ডেভেলপার লাগবে

- নতুন ধরনের পাতা, ফর্ম বা অ্যাডমিন ট্যাব দরকার হলে।
- সাইটের নকশা (রং, বিন্যাস) বদলাতে হলে।
- বোতাম বা শিরোনামের মতো স্থায়ী লেখা বদলাতে হলে, যা অ্যাডমিন প্যানেলে নেই।
- সাইট খুলছে না বা `/api/health` ঠিকানায় সমস্যা দেখালে (আগে DEPLOYMENT.bn.md-এর "সমস্যা হলে" অংশ দেখুন)।

## ৪. ডেভেলপারদের জন্য: লেখা ও অনুবাদ কোডের কোথায়

সাইট তিন ভাষায় চলে: বাংলা (bn), ইংরেজি (en), আরবি (ar)।

| কী | কোথায় |
|---|---|
| পাতা ও কম্পোনেন্টের স্থায়ী লেখা | `src/components/*.tsx`-এর ভেতরে `tr('বাংলা', 'English', 'العربية')` আকারে, যেখানে ব্যবহার সেখানেই |
| মেনু ও সাধারণ UI শব্দ (`t('...')`), সংখ্যা ও মুদ্রার রূপান্তর, ডাটাবেসের বাংলা লেখার ইংরেজি/আরবি রূপ (`localizeDynamicText`) | `src/utils/i18nContent.ts` |
| পাতার শিরোনাম ও সার্চ ইঞ্জিনের বিবরণ | `src/app/seo.ts` |
| প্রাথমিক (seed) তথ্য: কোর্স, নোটিশ, ফি, ইনফোগ্রাফিক ইত্যাদি | `src/data/*.ts` ও `src/server/db/seed-content.json` |
| ছবি ও লোগো | `public/assets/maharat/` |

**সতর্কতা:** seed তথ্য শুধু খালি ডাটাবেসে প্রথমবার এবং ডেমো মোডে ব্যবহৃত হয়। চালু সাইটের তথ্য ডাটাবেসে
থাকে, তাই seed ফাইল বদলালে লাইভ সাইটে কিছু বদলায় না; সেখানে অ্যাডমিন প্যানেল থেকে বদলাতে হবে।

নতুন লেখা যোগ করলে তিন ভাষাতেই দিন এবং পাশের কম্পোনেন্টের `tr()` ধরনটি অনুসরণ করুন।

## ৫. ডেভেলপারদের জন্য: নতুন তথ্য-সংগ্রহ (collection) বা অ্যাডমিন ট্যাব যোগ করা

গঠনের পুরো বিবরণ [ARCHITECTURE.md](ARCHITECTURE.md)-এ আছে। সংক্ষেপে ধাপগুলো:

1. **টাইপ:** `src/types/cms.ts`-এ নতুন আইটেমের টাইপ এবং `CMSState`-এ নতুন key যোগ করুন।
2. **চুক্তি (contract):** `src/server/contracts.ts`-এ key-টি `COLLECTION_KEYS` (আইটেমের তালিকা) অথবা
   `SINGLETON_KEYS` (একটি সেটিংস ডকুমেন্ট)-এ দিন এবং `RESOURCES_FOR_KEY`-তে লিখুন কোন অ্যাডমিন ট্যাবের
   অনুমতি এটি নিয়ন্ত্রণ করবে। TypeScript বাকি যেসব জায়গায় key-টি লাগবে সেগুলো ভুল হিসেবে দেখিয়ে দেবে।
3. **সংরক্ষণ:** ছোট তালিকার জন্য `src/server/db/prisma-tables.ts`-এ `generic('নতুনKey')` যথেষ্ট (নতুন টেবিল
   লাগে না)। বড় বা খোঁজার দরকার আছে এমন তালিকার জন্য `prisma/schema.prisma`-তে নতুন মডেল দিন; পরের
   বিল্ডেই টেবিল তৈরি হয়ে যায়।
4. **ভিজিটর কী দেখবে:** `src/server/state/project.ts`-এ ঠিক করুন key-টি সর্বসাধারণের কাছে যাবে কি না। ব্যক্তিগত
   তথ্য (ফোন, ইমেইল) কখনো পাবলিক করবেন না।
5. **যাচাই:** `src/server/state/validate.ts` ও `document-rules.ts`-এ নতুন তথ্যের জন্য zod নিয়ম যোগ করুন।
   ভিজিটর নিজে জমা দিতে পারলে `PUBLIC_CREATE_KEYS` ও `src/server/state/public-submit.ts` দেখুন।
6. **প্রাথমিক মান:** `src/data/seedData.ts`-এ খালি তালিকা বা ডিফল্ট মান দিন।
7. **স্টোর:** `src/store/useCMSStore.tsx`-এ যোগ/সম্পাদনা/মোছার ফাংশন লিখুন (শুধু `setState`; সার্ভারে পাঠানোর
   কাজ `src/store/sync/` নিজে করে)।
8. **অ্যাডমিন ট্যাব:** `src/utils/cmsLogic.ts`-এর ট্যাব-তালিকায় নতুন id ও `DEFAULT_RBAC_MATRIX`-এ অনুমতি দিন,
   `src/components/`-এ ট্যাবের কম্পোনেন্ট বানান এবং `AdminDashboard.tsx`-এ `activeTab === '...'` দিয়ে দেখান।
9. **পরীক্ষা:** যুক্তির জন্য পাশে `*.test.ts` লিখুন, তারপর নিচের সব পরীক্ষা চালান।

## ৬. ডেভেলপারদের জন্য: নিজের কম্পিউটারে চালানো ও পরীক্ষা

Node.js 22.13 বা তার পরের সংস্করণ (অথবা 24) লাগবে।

```bash
npm install
cp .env.example .env   # DATABASE_URL খালি রাখলে ডেমো মোড
npm run dev            # http://localhost:3000 (অ্যাডমিন: /admin)
```

GitHub-এ কোড পাঠানোর আগে চারটি পরীক্ষাই চালান:

| কমান্ড | কী পরীক্ষা করে |
|---|---|
| `npm run lint` | TypeScript-এর কড়া পরীক্ষা (অব্যবহৃত কোডও ধরে) |
| `npm test` | ইউনিট টেস্ট |
| `npm run build` | প্রোডাকশন বিল্ড (টাইপ পরীক্ষা → ডাটাবেসের টেবিল → Next.js বিল্ড) |
| `npm run test:e2e` | আসল ব্রাউজারে পুরো সাইট ও অ্যাডমিন প্যানেল (আগে `npm run build` লাগে) |

e2e পরীক্ষার জন্য একবার `npx playwright install chromium` চালাতে হয়। ডাটাবেস মোডে চালাতে চাইলে একটি
**নতুন, খালি** পরীক্ষার ডাটাবেস দিন (কখনো আসল সাইটের ডাটাবেস নয়):

```bash
DATABASE_URL="mysql://user:pw@127.0.0.1:3306/mmm_e2e" JWT_SECRET="কমপক্ষে-৩২-অক্ষরের-এলোমেলো-লেখা" \
  npm run test:e2e -- --db-push
```

বিস্তারিত `scripts/e2e/run.cjs` ফাইলের শুরুতে লেখা আছে।

**ডাটাবেসের গঠন বদলালে** (`prisma/schema.prisma`): Hostinger ও Vercel-এ পরের বিল্ডেই টেবিল হালনাগাদ হয়।
যে পরিবর্তনে তথ্য হারাতে পারে (কলাম বা টেবিল মোছা) সেটি বিল্ড নিজে থেকে করে না, বিল্ড থেমে যায়; এমন পরিবর্তন
আগে ব্যাকআপ নিয়ে হাতে করতে হয়। Cloud Run-এ `npm run db:push` নিজে চালাতে হয়।

**প্যাকেজ হালনাগাদ:** `package.json` বদলালে `npm install` চালিয়ে `package-lock.json`-ও কমিট করুন; সব হোস্টিং
এই ফাইল ধরেই একই সংস্করণ ইনস্টল করে। `next`, `prisma`, `@prisma/client`, `@prisma/adapter-mariadb` ও
`@next/env`-এর সংস্করণ সবসময় একসঙ্গে মিলিয়ে বদলান।
